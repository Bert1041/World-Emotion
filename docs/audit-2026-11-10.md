# World Emotion: pre-Phase-6 audit (2026-11-10)

Scope: the code on `main` plus PR #9 (Phase 5), run in real Chrome at phone (390×844, DPR 2) and laptop
(1440×900) sizes, plus the API on `wrangler dev`. Everything below is marked **confirmed** (seen in code or
in the browser), **potential** (plausible, not reproduced) or **recommendation** (opinion).

Shorthand: `web` = apps/web, `api` = apps/api, `core` = packages/core.

---

## 0. Verdict in four lines

- Engineering is well above the bar for a solo project: measured budgets, mutation-checked tests, real
  databases, decision records. It is not where the risk is.
- The product has a beautiful, honest first screen and **no second act**. The check-in ends in a chip that
  says "You feel stressed · change". No payoff, no comparison, no share, no reason to come back.
- The signature feature (six Earths, one per world mood) will almost never be seen: a pooled world of
  thousands of votes is stable, and hysteresis makes it more so. Most users will only ever meet one Earth.
- **Proceed to Phase 6**, with three pre-conditions (§8, P0/P1 "before Phase 6"). Do not plan a launch
  until the P1 "before launch" items are done.

## 1. Code quality and engineering

### What holds up (confirmed)
- `core` is pure, typed, and its purity is **enforced** by Biome `noRestrictedImports`, not by convention.
  380 tests, each mutation-checked per the phase reports; e2e at 11 viewports in real Chrome; D1 tests on
  real SQLite; migration forward + rollback with row counts; a traffic simulator in CI.
- Dependencies are minimal and justified (d3-geo, topojson, svelte, hono, zod). Initial JS 79 KB gz.
- API boundary is tight: exact-origin CORS, 1 KB body cap, strict Zod + ISO membership, HMAC'd device key,
  daily-rotating IP hash, idempotent upsert with `rows_written = 0` on replay, 503 with `Retry-After` on D1
  failure, missing-secret check. The `.dev.vars` leak into tests was caught and closed.
- i18n is structurally sound: whole-sentence templates, catalogues type-checked against English, plural
  rules via Intl, a test that fails on leftover English.

### What does not (confirmed unless marked)

**E1. `web/src/main.ts` is a 1,158-line god module.** It holds URL config, DOM lookup, layout fitting,
camera input (drag, fling, pinch, wheel), the frame loop, data → colour mapping, the check-in moment, the
pin, the demo data source, the bench harness and `verifyRender` (a ~65-line pixel-diff test that ships in
the production bundle). ~40 module-level `let`s are shared across all of it. There are **no unit tests**
for any of it; it is covered only indirectly by e2e. Phase 6 adds polling, a device key, an API client,
version rejection and (Phase 7) an offline queue. All of it would land in this file.
*Why it matters:* every Phase 6 feature touches state that five other concerns also mutate; e2e is the
only safety net and it is slow (12 min in CI).
*Fix:* split along the seams that already exist in the section comments: `input.ts` (gestures →
camera), `fit.ts` (layout + fitFrame), `checkin.ts` (pin, flight, ripple), `bench.ts` (`__bench`,
`verifyRender`, tree-shaken out unless `?bench=1`), leaving `main.ts` as composition + frame loop. Medium
effort, no behaviour change, e2e proves it.

**E2. The demo data source is wired into the frame loop.** `frame()` calls `sim.step()` every 2 s and
`checkIn()` calls `sim.checkIn()`. There is no `SnapshotSource` seam. Phase 6 has to replace this, and
the natural thing to do under time pressure is `if (config.demo) sim.step() else poll()` inside `frame()`.
*Fix:* define `interface SnapshotSource { subscribe(cb): unsubscribe; checkIn?(...) }` with `DemoSource`
and `PolledSource`; the frame loop never knows which. Do this first in Phase 6, before polling.

**E3. The world headline ignores the quiet state (defect against ADR 0003).** `onSnapshot` sets
`view.worldMood = next.world.h` unconditionally; `App.svelte` renders it. ADR 0003 §Consequences: "`h` for
the world with zero votes is happy (uniform-tie rule); the UI must show the quiet state from `n`, not
from `h`." README §5.4: "a world with zero votes renders the quiet state rather than a fake mood." Today
the demo never has `n = 0`, so nobody has seen it, but on launch morning the page will read
**"The world feels happy · 0 feeling something right now"**, which is fabricated data on the one screen
everyone sees. The region card handles quiet correctly; the header does not. *Fix:* a `quiet` branch in
the header below a threshold (`publishMinN` or a world-specific one), with copy and theme decided (which
Earth is the "nobody here yet" Earth?). Low effort, but it needs a design answer.

**E4. No failure path at all in the web app.** `start()` is `async` and nothing catches it. If the
TopoJSON import fails (slow data, a bad deploy, an ad blocker that hates `.json` chunks) the page is a
black screen with a headline and six disabled faces, forever, with no message. There is no loading state
either (0.6–1.0 s of black + header on a fast machine; several seconds on a slow 3G phone for 80k points
of 50m geometry). No offline state, no "snapshot stale" state. Phase 7/8 cover offline and limit-hit, but
"the map did not load" is not on any phase. *Fix:* a `try/catch` around `start()` with a visible message
and retry; a skeleton disc while loading. Low effort.

**E5. The user's own check-in is not remembered.** `view.checkin.mine` lives in memory. Reload and the
bar asks "How do you feel right now?" again, although (post-Phase 6) the server holds the vote. The pin
and language are persisted; the vote is not. *Fix:* persist `{mood, at, checkinId}` with the device key
(Phase 6, same place the device key is created).

**E6. Media queries are duplicated across CSS and JS** (`SIDE_CARD`, `DOCK_RIGHT` in `main.ts` and
`Panel.svelte`, mirrored in `index.html` with "must match" comments). Three copies of "what is
landscape" will drift. *Fix:* one CSS custom property read via `getComputedStyle`, or expose the query
strings from one TS module and inject them. Low effort, low urgency.

**E7. The device key is attacker-minted (potential, by design).** `deviceKey` is a client UUID; the
device limiter (3/min) therefore limits nothing an attacker cares about. The real limit is 10/min per IP
= 14,400 votes/day per IP. The privacy floor is 5 votes and shrinkage `k = 15`; ~50 votes from a handful
of VPN exits sets a mid-size country's headline. README says "Turnstile only on suspicious spikes"
(Phase 8). That is the right call for Phase 6, but it must be **before public launch, unconditionally
on the first check-in per device**, not "if we notice". Medium effort (Phase 8).

**E8. Early input before the map loads (potential, not reproduced).** Pointer listeners attach at module
load; `endDrag → hitAt → lods["50m"]` runs before `start()` has assigned `lods`. A tap on the canvas in
the first ~0.5–3 s should throw a TypeError in the handler. I could not reproduce it (my request-delay
hook blocked the whole module graph). One guard line; verify with a delayed-import test.

**E9. 2-s demo cadence and 20-s mood cycling are production code paths** (`autoCycle`, `?auto=0` in every
e2e). Fine for now; they go away with E2.

### Tests: what is missing
- Anything in `main.ts` (E1). Specifically: `releaseVelocity`, `releaseStretch` thresholds, `hitAt`,
  `regionOf`/`clarity`, `initPin` fallbacks. All pure enough to unit-test once extracted.
- A real Chrome test for the quiet world (E3) and the load-failure path (E4).
- Keyboard: there is no keyboard path to a continent or country at all (canvas only). The e2e suite
  cannot test what does not exist. This is the Phase 7 accessible list view; it is not optional for
  launch (see §3).

## 2. Architecture

**Appropriate, not over-built.** Static snapshot behind a CDN, one write endpoint, pure core, thin
adapters, measured budgets. The one place the architecture is thinner than it looks:

- **Everything client-side is one module** (E1/E2). The README's "four layers" exist in the canvas, not
  in the code organisation. This is the decision to make now, before Phase 6 doubles the client's
  responsibilities.
- **The world headline as the theme driver** is an architectural bet that will not pay: a pooled world
  with 3-minute smoothing half-life, 3-pt hysteresis margin and a 2-snapshot streak is designed to be
  stable, and a pool of thousands is stable anyway. Result: one Earth, nearly always. The six themes, the
  cross-fade, the OKLab mixer, the overlays: built, tested, invisible. Options: (a) the theme follows the
  **viewed** region (zoom into a stressed continent → Simulation Earth), (b) it follows **your country**,
  (c) keep world-driven and accept it is a rare event. I recommend (a): it makes zooming feel like
  travelling and reuses everything already built. Product decision; no code before it.
- **Privacy floor meets small countries.** With `publishMinN = 5` and complementary suppression, a user
  in Luxembourg, Iceland or Malta will see "Quiet here: showing Europe" for weeks after launch, and their
  own check-in will never visibly change anything. That is the right privacy call; the UX must say so
  *before* they vote ("Small countries show their continent until 5 people check in"), not leave them
  guessing.
- **Aggregation cadence vs. the check-in moment.** The demo counts your vote in 2 s. Production counts it
  in ≤ 5 min (plus smoothing). The flight-and-ripple animation covers the first second; the "+1" on the
  counter is a local fiction. This is fine *if* the copy is honest ("counted within 5 minutes"). It is a
  trust problem if the count ticks and the user's country does not move for an hour.

## 3. UI and visual

### Confirmed strengths (screenshots, both sizes)
Clear hierarchy (kicker → headline → count → globe → one action). One visual language (dark glass
cards, pill badges, one accent). Faces are drawn, consistent across platforms, always named. The map
colours are restrained; the night band and halo give depth. The landscape layout (side card, slim bar)
is genuinely good. "Text never on the Earth" is enforced by tests, and you can see it.

### Confirmed weaknesses
**U1. "Waterworld" under the headline is noise to a first-time user.** It is the theme name. Nothing
explains why it is there; it reads like a stray label. Either give it a role ("Calm world: the oceans
rise") or move it into the language of the card/onboarding. Low effort.

**U2. Particles render as hard squares and drift over open ocean.** At phone DPR they look like
rendering artefacts: blocky pixels over the Atlantic and Pacific far from any land. The README calls this
"mood weather"; on screen it reads as noise. Causes: `ctx.rect` squares, spawns at country centroids
with drift and no landmass constraint. Fix: round or soft sprites (one pre-rendered radial per mood,
`drawImage`), spawn inside the country's polygon or cull when over ocean, lower alpha. Medium effort;
needs re-benchmarking on the Pixel.

**U3. Small tap targets on the two most important secondary actions.** "move" and "change" are 0.82rem
text links (~12 px tall). WCAG 2.5.8 wants 24 px; platform guidance 44 px. Low effort: padding + min
height, no visual change needed.

**U4. Face labels are 0.72rem (≈ 10.8 px at the phone root size).** Readable on a bright 2× screen,
marginal outdoors. Consider 0.78–0.8rem; the bar has the height.

**U5. No loading state, no error state, no empty state** (E3, E4). Three of the five states the brief
asks about do not exist.

**U6. Country tap is undiscoverable.** Zoomed into a continent, nothing suggests countries are tappable;
the e2e knows, users do not. A one-time hint on first zoom ("Tap a country") or a subtle hover/press
highlight. Low effort.

**U7. Theme names as tone risk.** "Ruined Earth" with embers appears precisely when the world is angry,
i.e. after an atrocity. "Simulation Earth" for stressed is a wink that lands badly during a real crisis.
The parody framing is in the README; the moment a real event drives the world mood, screenshots of
"Ruined Earth" will travel. Product decision: keep (it is the brand), soften the names, or add a
"serious mode" the aggregator can flag.

Accessibility: contrast is fine (muted text ≈ 7:1), focus rings exist, `aria-live` on the headline and
card, reduced motion honoured and tested. The gap is structural: **no keyboard or screen-reader path to
any region data** (canvas). Phase 7's list view is the fix; it should be treated as launch-blocking, not
polish.

## 4. UX and journey (as a stranger, phone first)

1. **Open:** black, then a globe facing Africa/Europe, headline "The world feels calm". Understood in
   under two seconds. Good.
2. **The bar says "United States".** I am in Lagos with `en-US` Chrome (most of the world's English
   Chrome installs are `en-US`). `guessCountry` maps `en` → US. The badge is small and below the faces;
   most people will tap a face before reading it. With the Phase 5 rule, that vote then **counts for the
   world only**, and the app finds out from the response and says so *after*. First-run friction plus a
   silent-feeling downgrade on the very first action. This is the biggest journey defect.
   *Fixes, in order of cost:* (a) put the place **first**: "Checking in from United States · not you?"
   above the faces on first run; (b) spin the globe to the guessed country on load with the pin visible,
   so a wrong guess is obvious before the tap; (c) when the response says `counted: "world"`, offer the
   one-tap correction *and re-count* ("You seem to be in Nigeria. Count me there →" sends a second
   check-in with the right country; it is idempotent-safe and costs 2 rows). Decision A2 stands; this
   makes it survivable.
3. **Tap a face:** the face flies, the globe turns to my pin, a ripple, a haptic, the count ticks. This is
   the best moment in the app. Then: **"You feel stressed · change."** Nothing else. No "you and 1,204
   others", no "your country feels calm, you are in the 12 %", no share. The peak ends in a status line.
4. **Explore:** drag works, idle rotation is nice, pinch to a continent is clever but undiscoverable
   (nothing hints that you can zoom; tap works though). Peek card on phone is excellent. Country tap:
   undiscoverable (U6). Back: clear.
5. **Return tomorrow:** same screen, the app has forgotten I checked in (E5), nothing shows what changed
   since yesterday, nothing shows my own pattern. The only reason to return is "I wonder how the world
   feels", which is real but thin.
6. **Something goes wrong:** no message exists for any failure (E4).

Cognitive load is low; the unnecessary step is the hidden country correction. The missing step is the
reward.

## 5. Behavioural principles, honestly applied

| Principle | Relevant? | Today | Verdict / opportunity |
|---|---|---|---|
| **Trigger** (external/internal) | Yes | None. No notification, no widget, no daily artefact. Internal trigger ("how is everyone?") exists but is weak. | Cheapest external trigger with zero backend: a **daily world-mood post** generated by the aggregator (one image/text at a fixed UTC hour to a social account). Also the referral channel. Web push is possible without accounts but costs a Worker per send: later. |
| **Action** | Yes | One tap. Excellent. | Keep. Do not add steps. |
| **Variable reward** | Yes | The globe changes; the world mood almost never will (see §2). Region moods vary more. | Make the reward **personal and comparative**: "Stressed, like 14 % of Nigeria. Nigeria feels calm; the world feels calm." That varies daily and is free (it is in the snapshot). |
| **Investment** | Partly | Pin + language. The vote is forgotten (E5). | **On-device journal** (never sent): last 30 check-ins, a tiny strip "Your week: 😌😌😣😌😊". Zero backend, zero privacy cost, real loss aversion. The strongest single retention feature available to this architecture. |
| **Progress / streaks** | Weakly | None | Avoid streak guilt. A soft "12 check-ins · since 3 Nov" counter in the journal is enough. |
| **Discovery** | Yes | Zoom and country cards. Six Earths (rarely seen). | Theme-per-region (§2) turns every zoom into discovery. A "most extreme place right now" chip on the world view ("Chile is the happiest continent-sized thing today") is one `Object.entries` over the snapshot. |
| **Personalisation** | Yes | Country guess (often wrong), language. | Fix the guess (§4.2). Default the first zoom to the user's continent. |
| **Social / proof** | Core thesis | "You're not alone" is in the README, not on screen. | Show the number after the vote: "You and 1,204 others feel stressed right now." This *is* the product. |
| **Reciprocity** | Yes | The whole globe is visible before any action. Good. | Keep ungated. |
| **Loss aversion** | Yes | Nothing to lose. | The journal (above). |
| **Cognitive ease** | Yes | Very good. | Keep the bar; add the result below it, do not add a screen. |

None of the above needs accounts, a feed, or anything the non-goals rule out.

## 6. Product value and retention loops

**What problem it solves repeatedly:** a 10-second emotional check ("am I the only one?") with an
honest, beautiful answer. That is real; see the longevity of Hedonometer and the virality of
"We Feel Fine" and of r/place-style collective artefacts.

**Attract:** the globe + the headline, as a shared screenshot/link (the share card, Phase 7, is the
attract feature; it is not built).
**Activate:** one tap. Built, excellent.
**Repeat:** nothing yet. Needs: the comparative result, the on-device journal, a daily artefact.
**Loyalty:** the journal becomes a private mood history nobody else has; language + country remembered.
**Referral:** share card with the user's own line ("I'm one of 1,204 stressed people in Nigeria right
now") rather than the generic world card. Personal + social proof travels further.

**Loop (practical):** open → see world → tap → *see yourself among others* → (daily) notification-free
trigger via the shared daily post or the habit → journal grows → share when the world does something
unusual → new users.

**Why people would leave:** nothing changed since last time; it got the country wrong; a small country
that never shows itself; the blocky particles making it look unfinished; no answer to "so what?" after
voting.

## 7. Competitive thinking

- **Mood trackers (Daylio, How We Feel, Bearable):** personal history, reminders, insights. They do the
  *private* half; World Emotion does the *collective* half nobody does live. Do **not** copy their
  tagging, notes, or analytics. Borrow only the on-device journal strip.
- **Collective-sentiment projects (Hedonometer, We Feel Fine, Google Trends "Year in Search"):** passive,
  scraped, delayed. World Emotion's differentiator is *you pressed the button*: live, participatory,
  anonymous. Lean into that in copy.
- **Globe novelties (Earth wind map, ISS trackers, flight radars):** people return for *weather that
  changes*. Your "weather" is nearly constant at world level (§2). Region-level and time-of-day variation
  is where the change is; surface it.
- **Industry-standard things missing:** share card, install prompt, offline, a list view, OG preview
  (all Phase 7, correctly). Nothing else standard is missing; resist widgets and push until there is
  something new to push.
- **Avoid:** streaks with guilt, badges, leaderboards of countries ("happiest country" rankings invite
  brigading, exactly what the rate limits cannot stop), any free text.

## 9. Final assessment

| Area | /10 | Why |
|---|---|---|
| Code quality | **8** | Pure core, enforced purity, typed i18n, measured budgets, mutation-checked tests. Minus: `main.ts` (E1), zero unit coverage of client logic. |
| Architecture | **7** | The snapshot/CDN/one-endpoint design is right and cheap. Minus: client is one module; demo coupled to the loop; the theme driver is a bet that will not pay (T1). |
| UI design | **7.5** | Coherent, restrained, professional; landscape and peek card are excellent. Minus: particles read as artefacts, unexplained theme label, small targets, no loading/error states. |
| UX / usability | **6** | Two-second comprehension and a one-tap action. Minus: wrong-country first run, no payoff after the vote, undiscoverable zoom/country tap, nothing on failure. |
| Performance | **8** | 79 KB gz, dirty-flagged layers, LOD while moving, measured on a real Pixel 6 Pro. Minus: only a flagship was measured (ADR 0004 accepts the risk); 50m geometry load on slow data is unmeasured. |
| Differentiation | **7** | Live, participatory, anonymous, beautiful: nobody does this combination. Minus: the differentiating visual (six Earths) is mostly invisible in practice. |
| Engagement | **4** | One great moment, then a status line. No comparison, no social proof on screen, no discovery prompts. |
| Retention potential | **3** | No trigger, no investment, no memory of you, no reason tomorrow differs from today. All fixable within the no-accounts constraint. |
| Overall readiness (for Phase 6) | **7** | Yes, with the P0 and the three "pre-6" P1s. For launch: 4. |

### Five biggest weaknesses
1. No payoff after the check-in (R1): the product's thesis ("you're not alone") is never shown.
2. The world headline can fabricate a mood at `n = 0` (E3), and the theme it drives will rarely change (T1).
3. First-run country guess is wrong for most English installs and the downgrade is discovered after the vote (U-J2).
4. The client is one untested 1,158-line module with the demo data source welded into the frame loop (E1/E2), right before the phase that doubles its job.
5. No loading, error, offline or keyboard path (E4, A11y): three of the five UI states do not exist.

### Five biggest overlooked opportunities
1. **The comparative result line** ("you and 1,204 others; Nigeria feels calm"): free, immediate, the whole product in one sentence.
2. **An on-device journal** (never sent): the only investment mechanic compatible with the privacy stance, and the strongest.
3. **Theme per viewed region**: makes zoom a journey and finally shows the six Earths.
4. **A daily world-mood artefact** from the aggregator: an external trigger and a referral channel with no users to notify and no cost.
5. **Share the personal line, not the generic card**: "I'm one of N stressed people in X" travels further than "the world feels calm".

### If I took over as lead engineer
Before Phase 6: fix E3; extract `SnapshotSource`; split `main.ts`. In Phase 6: build the device key, the
response handling and the result line together, because they are one feature from the user's side.
Decide T1 and U7 now, as product decisions, so Phase 6/7 build toward them. Move the accessible list
view and the error states from "Phase 7 polish" to launch gates. Keep everything else exactly as it is:
the test discipline, the budgets, the decision records, the no-accounts line.

### What could prevent product-market fit
- **Cold start.** A globe that says "quiet" everywhere for a week is honest and dead. Plan the soft launch
  around a community that can produce 5+ votes per country of interest in the first hour (a subreddit, a
  newsletter, one city), and make the world count the hero until regions light up.
- **Brigading** a small country on day one becomes the story instead of the product (E7).
- **"So what?"** after the tap (R1). Beautiful and pointless is a one-visit app.
- **Tone** on a bad news day (U7).
- **Wrong country** on first run, so the first impression is "it doesn't know where I am" (U-J2).

### Is it ready for the next phase?
**Yes, for Phase 6**, on condition that E3 is fixed and E2/E1 are done first inside the Phase 6 branch
(they are prerequisites of the polling work, not extras), and that R1, U-J2, T1 and U7 are *decided*
before the Phase 6 design doc is written, because the response-handling code shape depends on them.
